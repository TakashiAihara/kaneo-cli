# Generating the API client from the OpenAPI document

## The problem

The client was hand-written: every request body and path was typed out from reading the server, and nothing checked them against what the server declares. Three of the 21 operations had drifted, and each failed only when run (all three reproduced with v0.2.1-rc.5 against a v2.29.2 server):

- `task move` sent `projectId`; the server reads `destinationProjectId` and answered 400
- `task assign` sent `assigneeId`; the server reads `userId` and answered 400, for assigning and for clearing alike
- `task create --assignee` sent `assigneeId`; the server ignored it and the task was created unassigned, without an error

`comment ls` had the same kind of drift on the way back: the author's name arrives as `user.name`, so `userName` was always empty.

## What changed

- `internal/api/gen` is generated by oapi-codegen-dd from `gen/openapi.json`, restricted to the operations in the registry
- `internal/api` keeps its methods and types, so the CLI layer and its JSON output are unchanged; each method now builds its request through the generated client and maps the generated response onto the CLI's types
- the generated client runs on a transport that goes through the same `send` as before: the key is refused over plain HTTP, dropped on a downgrading redirect, and a failure comes back as `*Error` with the server's message
- `board` reads every page of the task listing (see below)

## Which document it is generated from

The document shipped in a Kaneo release (`apps/docs/openapi.json` at the release tag), pinned by `KANEO_VERSION` in the Makefile and copied unchanged.

- rejected: the document the deployed instance serves. It follows whatever that one instance runs, so the generated code would change with someone's upgrade schedule, and a public client should target a release rather than a deployment
- rejected: fetching the document at build time. The build would depend on the network and the output would change without a commit

For v2.29.2 the file at the tag and the document a v2.29.2 server serves are identical for all 21 operations (compared 2026-09-30). The release document is also far more complete than older ones: v2.29.2 types the board, the relations and the assignee fields, which an older release leaves as a bare `object`.

## What the overlay corrects

`gen/overlay.json` holds the corrections, each with the condition for removing it. They fall into two groups:

- the document is wrong: better-auth's organization routes are described with empty schemas, so the workspace listing and rename decode to nothing without one
- the generator is wrong: an empty schema becomes `struct{}`, which rejects a string (external-link metadata, activity event data), and a required nullable field gets `omitempty`, which drops the `null` that clears an assignee

The overlay is JSON because oapi-codegen-dd v3.75.20 fails to apply a YAML overlay to a JSON document.

## Paging the board

v2.29.2 pages the task listing: 50 tasks by default, 100 at most. Older releases returned every task in one page. Read as one call, a board past 50 tasks would lose the rest without an error, so `GetBoard` asks for 100 per page and reads until `totalPages`, merging columns that recur across pages.

A page's labels, links and columns are paged again (`relatedPage`). Reading that level is not implemented; a board that needs it fails instead of coming back with labels missing.

## Compatibility with older servers

Requests are the same shape on older releases for these 21 operations, and responses decode with the release's types. Against the deployed instance (older than v2.29.2), `task list --all` and `project ls --archived` produced byte-identical output with the old and the new build.

## Cost

- Go 1.27 (the generated runtime needs at least 1.25.7; the latest release was taken)
- the runtime pulls in `go-playground/validator`; the stripped binary grows from 7,680,263 to 8,327,431 bytes
- the generator is a `go tool` dependency, so the generator and the runtime are the same version by construction
